# sample — 1단계 기획

## ① 목적 문장
7단계 AI 개발 플로우의 자가 검증을 위해, 매일 아침 서울 날씨를 한 줄 문장으로 텍스트 파일에 기록하는 소형 도구를 3주(21일) 연속 운영으로 증명한다.

## ② 범위

### 포함
| 영역 | 현재 상태(기존 코드가 있으면 경로) | 비고 |
| --- | --- | --- |
| 날씨 조회 | 없음 (신규) | 외부 날씨 API 1회/일, 읽기 전용 |
| 문장 생성 | 없음 (신규) | LLM 미사용 — 틀 문장 방식 |
| 파일 덧붙이기 | 없음 (신규) | 텍스트 파일에 하루 1행 추가(append) |

### 제외
- 알림 발송 (푸시·이메일·SMS 등 모든 형태)
- 웹 화면 또는 API 서버
- 서울 외 다른 도시
- LLM 기반 문장 생성
- 명시하지 않은 모든 기능

### 바꾸지 않을 현행 동작 (2단계 §0 현행 기록의 출발점)
해당 없음 — 신규 개발, 현행 코드 없음.

### 바꿀 수 있는 동작
해당 없음 — 신규 개발.

## ③ 성공 기준

### SC-1 실행 완료율
- **숫자**: 21일 운영 기간 중 누락 0일
- **측정 방법**: 운영 종료 후 텍스트 파일의 총 행 수가 21인지 확인
- **측정 시점**: 21일 운영 종료 직후 (6단계 검증)
- **현행 값**: 확인 못 함 — 신규 개발

### SC-2 데이터 정확도
- **숫자**: 기온·강수 숫자의 API 응답 대비 불일치 0건
- **측정 방법**: 각 행의 기온·강수 값을 해당일 API 응답 로그와 대조
- **측정 시점**: 21일 운영 종료 직후 (6단계 검증)
- **현행 값**: 확인 못 함 — 신규 개발

### SC-3 실행 시각 정확도
- **숫자**: 매일 07:00 ± 5분 이내 실행
- **측정 방법**: 실행 타임스탬프를 로그에서 추출하여 07:00 기준 편차 확인
- **측정 시점**: 21일 운영 종료 직후 (6단계 검증)
- **현행 값**: 확인 못 함 — 신규 개발

## ④ 지킬 선
1. **API 키 보호**: API 키는 환경 변수로만 관리한다. 로그·코드·설정 파일에 노출되면 키 유출로 이어진다.
2. **파일 불가역성**: 텍스트 파일은 덧붙이기(append)만 허용한다. 기존 행을 지우거나 덮어쓰면 운영 이력이 손실된다.
